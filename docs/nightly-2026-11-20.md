## UWP reuse

The November 20 local UWP evidence was read at
`816ace2b0ae701766b572d639a86aa753f78e166`. The port is at `2e0c79dfd` and the
shared Wasm standard library packaging follow-up is at `7d0cd1f6a`. The
published UWP nightly branch at inspection was November 18 at
`2e98d4555313e2d9485c207ddc1962e2636001bd`. The November 20 local worktree had
an active patch edit. Only committed sources were used for the comparison.
[Published UWP runtime report](https://github.com/megabytesme/MCHorizonUWP/blob/2e98d4555313e2d9485c207ddc1962e2636001bd/docs/nightly-mod-runtime-2026-11-20.md)

| Reuse class | Wii U application |
| --- | --- |
| Direct | Use upstream package manifest, API, digest, native revision and dependency validation. Reuse the UWP hook fixtures, source inventory checks and exact-build preflight design. Preserve the stock dependency ordering and typed hook factories. |
| Platform adapters | Compile explicitly trusted API-only mod crates in the Cafe build graph and register their factories at hosted startup. Use Cafe's allocator, target lock and link map. Prefer verified staged source and resource generations with atomic promotion. Test the entire launch and return cycle because UWP found a process-wide mod registration seal that already survived a launcher return. |
| Platform replacements | Keep WHB and ProcUI, the Cafe allocator and socket glue, controller and keyboard bridges, GX2 and the verified RPX/WUHB package process. UWP's AppContainer import and TLS template checks inform Cafe's corresponding link and startup checks. |
| Research | UWP's Wasmtime 50.0.2 Pulley proof covers ARM32. PowerPC32 needs independent compiler and big-endian ABI proof, including little-endian Wasm memory, typed host calls, atomics, guard and trap behavior, epoch budgets, bounded memory, cache identity, dependency groups and a bounded native and guest stack. Require real game hooks and trap isolation before enabling the executor. Native source mixins and typed injections need their respective upstream generators and transformed-source verification. |

### Upstream interfaces

| Area | November 20 source and Cafe verification needed |
| --- | --- |
| Startup, shutdown and integrated server | `entry.rs` separates launch validation, package and code startup, hook registration and dispatch. `game/world/integrated.rs` and `game/world/saving.rs` own integrated lifecycle and saving. Hosted entry needs a session-scoped path around the desktop executable and process exit. Confirm server join, flush and tool withdrawal twice inside one process. |

| HMOD | `horizon-mod-package`, `horizon-mod-runtime`, `horizon-mod-deps` and `horizon-mod-wasm` replace the old crate arrangement. Start with real content package integration. Builder-linked native code and a sandboxed Wasm executor require separate Cafe evidence. |
| Cargo and target | The workspace declares Rust 1.95 minimum. Nightly SDK uses 1.99.1 and Cafe uses its pinned 1.101.0-dev stage1. The compiler version clears the minimum. PowerPC32 imports, target-specific crate code and the new locked graph still require native build verification. |

## First Cafe source stage

[0001-cafe-core.patch](../patches/0a875da91dbb0fdcb7ba8c42c11341aa229af51a/0001-cafe-core.patch)
retains 0.7.0's normalized Cafe cache root and prepared-file lookup. It keeps
the new desktop parallel writer and gates its gameplay startup call on Cafe,
which uses the desktop-prepared cache. The new Java map and density cache
identity counters use native atomics where available and the existing
`portable-atomic` 1.15.0 fallback on PowerPC32. Both counters retain their
64-bit width.

| Source check | Value |
| --- | --- |
| Input tree | `84463ab1b850d9ac382fb0b94d247f0c06d690fc` |
| Patch SHA-256 | `c51e664a3bd5c24e615fdfb8df08424ea079ee9ec60efd991ba271eb7afab163` |
| Output tree | `2f3fa5fbb01226b6526d9369ddbefc088f72c144` |

Independent index replay reproduced the output tree. Ben-Desktop ran these
commands in an isolated WSL 2 checkout of the exact source with the patch
applied. The native command used the pinned Cafe toolchain from the
[input lock](../catalog/toolchain-cafe-v1.json).

```sh
cargo +nightly test --offline --locked -p horizon-core --lib
RUSTC="$HORIZON_WIIU_STD_RUSTC" cargo +nightly build --offline --locked \
  --target powerpc-nintendo-cafe --release -p horizon-core --lib
```

The host run passed 210 tests with eight ignored, including nine prepared-file
tests. The native release archive built successfully. Its LLVM data layout
specified big-endian 32-bit PowerPC. This stage is ready for consumption by
the future Nightly recipe. The active 0.7.0 catalog still selects its original
inputs. The hosted resource startup call and in-game cache read remain pending.
