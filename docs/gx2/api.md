# GX2 reference for the hosted port

Build inputs were checked against installed WUT 1.9.2-1 in
`/opt/devkitpro/wut/include`. The native builder records the hash of the
installed header inventory, compiler and CafeGLSL executable. Installed
declarations define the callable interface. WHB source explains the
helpers' implementation. [WUT GX2 declarations](https://github.com/devkitPro/wut/tree/v1.9.2/include/gx2),
[GX2R declarations](https://github.com/devkitPro/wut/tree/v1.9.2/include/gx2r),
[WHB presentation and allocation](https://github.com/devkitPro/wut/blob/v1.9.2/libraries/libwhb/src/gfx.c).

| Need | Available APIs and current usage | Port guidance |
|---|---|---|
| Shader programs and inputs | `gx2/shaders.h`: `GX2SetShaderMode`, `GX2SetVertexShader`, `GX2SetPixelShader`, `GX2SetFetchShader`. `WHBGfxLoadGFDShaderGroup`, `WHBGfxInitShaderAttribute` and `WHBGfxInitFetchShader` used by HUD, terrain and panorama. CMake compiles GLSL offline, then embeds GFD. | Use one GFD variant per stable material state. Verify reflected attributes, sampler locations and register offsets. Fail the resource on missing reflection entries. WGSL needs a deliberate GLSL/GFD translation and pass-specific validation. |
| Uniform and resource binding | `GX2SetVertexUniformReg` and `GX2SetPixelUniformReg` pass 4-component values. Terrain writes clip rows, section origin and fog. HUD selects per-run state and texture; `GX2SetPixelTexture` and `GX2SetPixelSampler` bind reflected slots. `GX2Set{Vertex,Pixel}UniformBlock` and GX2R equivalents exist. | Bind projection-invariant constants, fog, texture and pipeline once per output/pass. Draw only changes per-section values and buffers. For larger constant tables evaluate uniform blocks using the declared alignment and matching shader mode. |
| Vertex formats | `gx2/enum.h` and fetch shader layout. Native terrain uses 40-byte position, color, UV and cutoff floats. HUD uses its own raw vertex ABI. Existing native attributes include `GX2_ATTRIB_FORMAT_FLOAT_32_32_32_32` and packed color formats. | Validate field offsets in both C and Rust and choose endian-aware fetch formats. A smaller native vertex needs independently tested UV, light and position decoding. Count both bandwidth and varying/interpolator use. |
| Vertex/index storage and draw submission | `gx2/draw.h`: `GX2SetAttribBuffer`, `GX2DrawEx`, `GX2DrawIndexedEx`, `GX2DrawIndexedImmediateEx`; `gx2r/draw.h`: `GX2RSetAttributeBuffer`, `GX2RDrawIndexed`. Terrain uses retained GX2R vertex buffers and a shared 32-bit quad index buffer. HUD submits runs; panorama submits 36 vertices. | Preserve order for blending. Track active draw counts and source indices. Evaluate display lists or instancing only with static state or compatible per-instance data. Separate section lifetime from CPU mesh lifetime. |
| GX2R storage and arenas | `GX2R{Create,Destroy,Lock,Unlock}Buffer` and surface variants, with `Ex` suffixes where declared. `GX2RCreate{Buffer,Surface}UserMemory` and allocation size/alignment APIs support owned backing pools. WHB installs its GX2R allocator. Resource flags express bind/use, CPU write/read, GPU write/read and forced MEM1/MEM2. | Reserve foreground MEM1 and scan-related memory for latency-sensitive targets within WHB's ownership. Use proven aligned pools for large retained resources. Measure `MEMGetTotalFreeSizeForExpHeap` plus the largest aligned block, BSS overhead, GX2 target sizes and requested Rust live/peak bytes. An unavailable heap probe means heap totals are unknown. |
| Texture shape, format, pitch and swizzle | `GX2CalcSurfaceSizeAndAlignment`, `GX2InitTextureRegs`, `GX2GetSurfaceSwizzle` and `GX2SetSurfaceSwizzle` in texture/surface headers. RGBA8 native atlases use linear aligned pitches. Readback uses a linear special destination. GX2R creates storage from the surface descriptor. | Derive layout and bounds from the actual surface descriptors and view mip/slice values. Use the computed pitch for CPU copies. Evaluate a tiled GPU destination via `GX2CopySurface`. Populate bytes using the destination's actual layout. |
| Texture upload and coherence | `GX2RLockSurfaceEx`, `GX2RUnlockSurfaceEx`, `GX2RInvalidateSurface`, `GX2Invalidate` and CPU `DCFlushRange`/`DCInvalidateRange`. Terrain atlas uploads pitched rows, HUD handles patch rows. Buffer/texture uses and invalidation modes are declared in `gx2r/resource.h` and `gx2/enum.h`. | Cache maintenance and GPU lifetime are independent. Bind correct producer/consumer flags. Track dirty rows and aligned spans. Narrow invalidation only with physical texture readback evidence because Cemu can mask coherency errors. |
| Sampling, arrays and mips | `GX2InitSampler`, `GX2InitSamplerXYFilter`, `GX2InitSamplerZMFilter`, `GX2InitSamplerLOD`; surface dimensions enumerate 2D and array resources. HUD uses point, linear and repeating samplers depending on run. Terrain is point-clamp and one mip. | Port terrain repeat, per-sprite border and mip generation together. Compare arrays with texture atlas paging using compiled shader and VRAM measurements. Budget texture views/samplers per shader through reflection. Treat the presenter's reported dimensions as a port cap, not a verified hardware allocation guarantee. |
| Blend, channel and alpha controls | `GX2SetBlendControl`, `GX2SetColorControl`, `GX2SetTargetChannelMasks`, `GX2SetAlphaTest`. HUD selects ordinary, invert, multiply/vignette, additive and glint states. Solid terrain disables blending and performs foliage discard in GLSL. | Keep alpha cutoff, blending equations, separate alpha factors and draw order from Horizon. Check destination alpha and sRGB behavior against pixel references. For translucent terrain keep tested solid depth and disable depth writes where the reference requires it. |
| Depth/stencil and target context | `GX2SetDepthOnlyControl`, `GX2SetDepthStencilControl`, `GX2SetDepthBuffer`, `GX2ClearDepthStencilEx`, `GX2SetContextState` and WHB context getters. Terrain uses LEQUAL. The HUD preview restores context and rebinds both color and depth after clearing. | Preserve depth clear value, range and comparison as one decision. Add explicit context, color/depth and state rebinding at handoff boundaries. Check physical preview tests after changing the ordering. |
| Viewports, scissors and clipping | `GX2SetViewport`, `GX2SetScissor`, `GX2SetRasterizerClipControlEx`, `GX2SetCullOnlyControl`. Target callbacks receive actual surface dimensions. | Derive per-output aspect and viewport once. Preserve HUD logical dimensions and each nested clip. Tie any conservative section cull to the actual GX2 clip convention and camera pose. |
| Color targets, transitions and post-processing | `GX2InitColorBufferRegs`, `GX2SetColorBuffer`, `GX2ClearColor`, `GX2CopySurface` and `GX2Invalidate` with appropriate resource modes. `loading_host.c` reads back from the WHB target. The normal path has no extra full-resolution post target. | When a pass samples a previous target, allocate compatible surface views, finish writes, invalidate the appropriate GPU cache and avoid sampling a destination still in use. Prefer one modest temporary surface where possible, use paired surfaces for feedback only when necessary. |
| Completion, swap and command lifecycle | `GX2GetSwapStatus`, `GX2WaitForVsync`, `GX2WaitForFlip`, `GX2GetSwapInterval`, `GX2SetSwapInterval`, `GX2Flush`, `GX2DrawDone`, `GX2GetLastSubmittedTimeStamp`, `GX2GetRetiredTimeStamp`, `GX2WaitTimeStamp`. WHB waits for prior flip in begin and swaps, flushes, waits and enables outputs in finish. Many native paths also call `GX2DrawDone`. | Classify waits before attempting to remove them. Mutable HUD and panorama buffers, readback copies, resource destruction and ProcUI release require explicit ownership. Retired submission timestamps can bound reuse after validation. They do not independently report elapsed GPU cycles. |
| GPU fences and timing | `gx2/semaphore.h::GX2SetSemaphore` requires 8-byte alignment. The WUT import table also names `GX2SetGPUFence`, but the installed public event header does not declare its prototype. `gx2/debug.h` does not establish a portable elapsed-time query API. | Use installed, declared APIs first. Treat host wall time around GX2 submission, blocking waits and swap as distinct measures. Physical experiments may compare fixed workloads through retirement and supported fences after verifying semantics. Avoid claiming GPU execution time from Cemu or command submission timestamps. |
| TV/GamePad and ProcUI | `GX2CopyColorBufferToScanBuffer`, `GX2SwapScanBuffers`, TV/DRC display APIs and WHB per-output begin/finish functions. `cafe_host.c` handles the ProcUI pump. The two outputs draw separately with shared retained terrain and textures. | Sharing a camera pose or geometry does not imply identical viewports. Resolve draw order and depth independently; preserve mode capabilities and ownership during HOME release and reacquisition. Log active output sizes and observed flip cadence. |

The referenced WHB functions' shader loading and coherent shader allocation
are documented in [WUT's GFD shader support](https://github.com/devkitPro/wut/blob/v1.9.2/libraries/libwhb/src/gfx_shader.c).
The `gx2r` and `coreinit/cache.h` headers describe available controls, but a
header alone cannot prove a cache hazard is fixed. Validate real display and
texture behavior before moving storage or removing waits.

## Retirement evidence in Cemu

In the pinned Cemu 2.6 build, `GX2WaitTimeStamp` waits for the retirement
marker that the emulated Latte command processor publishes. The handler
publishes the value when it processes the marker. `GX2DrawDone` also
queues a separate asynchronous-readback and occlusion-query sync command
in the Vulkan renderer. Removing a draw drain can therefore change both
submission pacing and which Vulkan readbacks have completed when the
test reads them. [Cemu GX2 event implementation](https://github.com/cemu-project/Cemu/blob/a6fb0a48eb437a8a41c13b782ac8ae0433bf8f98/src/Cafe/OS/libs/gx2/GX2_Event.cpp) ·
[Cemu command processor](https://github.com/cemu-project/Cemu/blob/a6fb0a48eb437a8a41c13b782ac8ae0433bf8f98/src/Cafe/HW/Latte/Core/LatteCommandProcessor.cpp)

Qualify a deferred finish in ordinary independent-output gameplay with
readback disabled in the timing window. Track the advancing command
watermark, the paired scan publication and a changing per-output sentinel.
Exercise readback and foreground release in separate runs and keep their
existing completion path. Resource reuse still needs the physical check
that the oldest submitted work has finished reading each reused slot.
