# GX2 integration contract and work packages

This is the coordination plan for running the existing Horizon client on Wii U.
The first milestone is the original, interactive startup menu; later work connects
the original game and terrain. `PORTING.md` records the evidence and limitations
of individual experiments. A diagnostic rendering a captured desktop batch is not
an interactive Cafe client.

## Boundary

- Horizon owns menu state, layout, game logic, resources, `gfx::Frame`, `HudBatch`,
  `HudAtlas`, and terrain meshes. The Cafe host supplies lifecycle, input and GX2
  presentation. Feed it live data generated by the Cafe client, not a capture from
  the desktop renderer. Desktop paths remain functional.
- Use the existing `PresentationBackend` and `TerrainBackend` seams where they fit;
  they currently live in the desktop-oriented renderer and are not yet selectable
  by the Cafe client. Adapt the smallest demonstrated boundary rather than clone
  Winit or WGPU or move whole subsystems speculatively. Unsupported operations
  must be reported, not silently treated as successful.
- One render thread owns WUT lifecycle and GX2 initialization, presentation and
  teardown. A presenter borrows frame geometry and patches synchronously; it does
  not retain them after submission. Its shader data outlives it. It copies the
  atlas on creation and checks its revision and dimensions. Recreate the presenter
  when the atlas revision changes, coordinating this with target recreation.
  Texture dimensions, allocation and shader capabilities must be checked on the
  actual backend.
- Preserve the order of HUD runs, viewport and scale, atlas updates and supported
  blending. Do not claim support for a frame pass or blend until it is implemented.
  An error or unsupported pass must not be reported as a displayed frame. UI layout
  may drain pending glyphs into a transient batch before submission. After a rejected
  frame or renderer recreation, reset both the font and `ui_theme` atlas caches and
  redraw the batch from Horizon state before retrying.
  Create the presenter and reset caches before laying out the first new batch.
- The existing `HorizonPresenter` and C HUD renderer already accept original HUD
  data. Panorama and terrain have diagnostic paths; they are not yet production
  client integration. The existing `PresentationBackend` alone does not convey
  every atlas or resource operation needed by this path.

## Work packages

Owners should agree on interface changes before editing a shared file. Each package
ends with a focused review, appropriate host and Cafe checks, and a record of what
was actually verified. Parallel work should use separate branches or nonoverlapping
files and should not overwrite uncommitted work.

1. **Cafe lifecycle and input.** Own the Wii U host under `wiiu/` and its platform
   input/lifecycle code, but not `game.rs`. Initialize and tear down WUT and GX2
   once. Supply VPAD transitions from the existing `VpadState` to the integration
   boundary; package 3 connects them to Horizon's existing pad/menu processing.
   Completion: the real host drives original startup and an input changes the menu
   state in Cemu; the integration depends on package 3.
2. **Live title presentation.** Own the Cafe presentation bridge and panorama
   path, not desktop renderer selection. Extend and integrate the existing
   `HorizonPresenter` and HUD renderer rather than building another HUD bridge.
   Consume live `Frame`, atlas, batch and original panorama data through the
   agreed integration boundary; initialize resources before layout and apply the
   failure/recovery contract above. Add title/menu passes required by observed real
   frames, reporting unsupported features explicitly. Verify TV and GamePad output
   separately. Completion: an interactive original Cafe title/menu is visible in
   Cemu, with screenshot and input evidence. This depends on packages 1 and 3; a
   host-generated replay does not satisfy it.
3. **Client selection and handoff.** Sole owner of necessary upstream `Loading`,
   `Game`, entry and renderer-selection changes, including `game.rs`. Agree the
   host and presenter boundary with packages 1 and 2 before changing shared code.
   Loading's platform helpers exist, but its lifecycle remains private and coupled
   to Winit and `Renderer`; connect the native host and presenter while keeping
   desktop construction intact. Account for `Loading::finish` handing off to
   `Game` after title acceptance, before world selection. Completion: the actual
   client builds for Cafe and advances through that handoff with the other packages,
   without substituting a diagnostic client or claiming unsupported success.
4. **Terrain integration, after the menu path.** Own GX2 section resources and
   the adapter from original `SectionMesh`/section keys. Replace a section
   atomically on successful upload, retain no borrowed mesh, preserve the previous
   section on failure, and implement section removal and clearing. Use the original
   streaming and mesher data; add required opaque, cutout, translucent, lighting or
   other passes as the real frames demand, and report gaps explicitly. Completion:
   real client-produced section upload, replacement and removal are visible and
   checked in Cemu; diagnostic one-mesh output alone does not qualify.
5. **World safety and hardware verification.** Independently validate the live
   client, failures, lifecycle and resource cleanup, first in isolated Cemu data
   and then on the console when practical. World entry also requires a verified
   equivalent to Horizon's session lock: Cafe `File::try_lock` is unsupported and
   the Cemu filesystem probe allowed concurrent opens. Do not bypass it or use a
   non-atomic lockfile as if it provided exclusivity. Record Cemu versus hardware
   results separately, and use scratch game homes and saves throughout testing.

The packages can be investigated in parallel, but 1–3 must converge on one
working title/menu path before treating the client milestone as complete. Package
4 depends on the real client handoff; package 5 reviews and tests throughout.
